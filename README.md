# TurboBloxels

Конструктор игр в духе **Bloxels**: доска 13×13, персонаж из пикселей, «Книга правил» и
платформер, в который можно играть сразу в браузере. Главная фишка — **расширения на
JavaScript**: свой файл добавляет новые блоки, их поведение и даже новые действия для
книги правил.

Клиент — чистый ES-модульный JavaScript без сборки, сервер — Node.js + Express,
хранилище — один JSON-файл. Никаких внешних CDN, шрифтов и картинок: все спрайты и звуки
генерируются кодом.

```
npm install
npm start          # http://localhost:3000
npm test           # 47 тестов: сервер, движок, правила, песочница, клиент в jsdom
```

## Что умеет

| Возможность | Где |
| --- | --- |
| Доска 13×13, до 12 экранов подряд, кисть/ластик/заливка/пипетка, undo/redo | `#/editor` |
| Конструктор персонажа 13×13, цвета дают способности | `#/editor` → «Персонаж» |
| Рисунок фона с параллаксом | `#/editor` → «Фон» |
| **Книга правил**: «когда → если → то» для каждого блока | `#/editor` → «Книга правил» |
| Платформер: бег, прыжок, двойной прыжок, рывок, вода, лёд, лестницы, враги, шипы, лава, батуты | `#/play/:id` |
| Мастерская расширений с песочницей и публикацией | `#/extensions` |
| Каталог уровней, лайки, таблица результатов | `#/levels` |
| Аккаунты, черновики в браузере, публикация в облако | весь интерфейс |

## Блоки — это правила

Уровень — это доска, а **смысл блока задают правила**. Правило состоит из трёх частей:

```
КОГДА  персонаж входит в блок
ЕСЛИ   [только один раз за прохождение]
ТО     +1 очко · звук «coin» · частицы · убрать блок
```

События: `вход`, `касание`, `стоит`, `приземление`, `удар снизу`, `каждые N секунд`,
`кнопка E`, `старт`.
Условия: `once`, `есть способность`, `очков ≥ N`, `сердец ≥ N`, `сердец < N`, `шанс N%`.
Действия: очки, сердца, подбросить, ускорение, неуязвимость, убрать/заменить блок,
сообщение, звук, частицы, телепорт, выпустить врага, победа, поражение, действие расширения.

Всё это редактируется мышкой в «Книге правил» и хранится в данных уровня (`data.rules`),
поэтому два уровня с одинаковыми блоками могут играться совершенно по-разному.
Подробнее — `#/docs` в приложении и [docs/EXTENSIONS.md](docs/EXTENSIONS.md).

## Расширения на JavaScript

Расширение — обычный JS-файл, который вызывает `TBX.define({...})`:

```js
TBX.define({
  id: 'my-pack',
  name: 'Мой набор',
  version: '1.0.0',
  blocks: [
    {
      id: 'jelly',
      name: 'Желе',
      color: '#ff8fd0',
      solid: true,
      restitution: 1.2,          // прыгучесть
      pattern: ['.............', '....++###....'], // рисунок 13×13
      rules: [
        { trigger: 'stomp', actions: [{ type: 'bounce', value: 20 }, { type: 'sound', value: 'bounce' }] },
      ],
      on: {
        enter(ctx) { TBX.log('желе на', ctx.x, ctx.y); },
      },
    },
  ],
  hooks: {
    onStart(ctx) { TBX.message('Погнали!'); },
    onTick(ctx) { /* ~4 раза в секунду */ },
  },
});
```

Своё действие для книги правил:

```js
TBX.action({
  id: 'quake',
  name: 'землетрясение',
  value: 'number',
  run(ctx, power) {
    TBX.message('Землетрясение!');
    for (let i = 0; i < 18; i++) TBX.particles(ctx.x, ctx.y, '#ff9f43', 2);
  },
});
// в правиле: { trigger: 'use', actions: [{ type: 'ext', value: 'my-pack:quake' }] }
```

Готовые примеры — в каталоге [`examples/`](examples), их же можно загрузить кнопкой
«Примеры» в мастерской.

### Безопасность песочницы

Код расширения не исполняется на странице игры:

* каждое расширение живёт в отдельном `iframe` с `sandbox="allow-scripts"` — без
  `allow-same-origin`, то есть с opaque origin: нет доступа к DOM, cookie, `localStorage`;
* у документа песочницы своя CSP: `default-src 'none'`, `connect-src 'none'` — сеть
  запрещена полностью, `eval` разрешён только для загрузки кода расширения;
* общение — `postMessage` с меткой `tbx: 1`, команды из белого списка
  (`score`, `damage`, `setBlock`, `particles`, …) проверяются и ограничиваются по
  диапазонам на стороне игры;
* ошибки и `console`-подобный вывод не роняют игру — они показываются в логе мастерской;
* исходник ограничен 100 КБ и проверяется на сервере.

Расширение всё равно стоит читать перед установкой: внутри разрешён любой JS, включая
тяжёлые циклы (у них есть лимит команд и времени загрузки).

## API в двух словах

`POST /api/auth/register|login`, `GET /api/auth/me`,
`GET|POST /api/levels`, `GET|PUT|DELETE /api/levels/:id`, `POST /api/levels/:id/play|like|score`,
`GET /api/levels/:id/leaderboard`, `GET|POST /api/extensions`, `GET|PUT|DELETE /api/extensions/:id`,
`POST /api/extensions/:id/like`, `GET /api/stats`.
Авторизация — `Authorization: Bearer <token>` (токен выдаётся при входе) или cookie `tbx_token`.

В локальном режиме (GitHub Pages) те же маршруты обслуживает `public/js/localdb.js`
без сети: ответы и коды ошибок совпадают, только вместо базы — `localStorage`
(ключ `tbx.localdb.v1`).

Переменные окружения: `PORT` (по умолчанию 3000), `HOST` (0.0.0.0), `TBX_DATA_DIR` (по
умолчанию `./data`). Данные лежат в `data/db.json`, каталог в `.gitignore`.

## Как выложить на GitHub

Есть два способа, и клиент сам понимает, в каком он оказался.

### 1. GitHub Pages — статика, без сервера (проще всего)

В репозитории уже лежит workflow `.github/workflows/pages.yml`: он прогоняет тесты и
публикует папку `public/` целиком.

1. Запушьте проект в GitHub (ветка `main`).
2. Откройте **Settings → Pages → Build and deployment**.
3. В поле **Source** выберите **GitHub Actions** (не «Deploy from a branch»).
4. Сделайте пуш в `main` или запустите workflow вручную: **Actions → GitHub Pages → Run workflow**.

Через минуту игра будет на `https://<логин>.github.io/<репозиторий>/`.

Что важно знать про такой режим:

* сервера нет — клиент сам переключается в **локальный режим** и обслуживает тот же REST
  контракт из `public/js/localdb.js` поверх `localStorage`;
* уровни, расширения и аккаунт живут **только в этом браузере**; чужие уровни не видны,
  а очистка данных сайта их удалит (демо-уровень и два примера расширений вернутся);
* ссылки на «Поделиться» работают между вкладками того же браузера, но не между людьми;
* всё работает и с `file://`, и в подкаталоге — пути в `index.html` относительные,
  а адрес песочницы вычисляется от `import.meta.url`;
* принудительно включить локальный режим можно через `?local=1`.

Если позже поднимете сервер (см. ниже), достаточно вписать его адрес в `public/config.js`:

```js
window.TBX_API_BASE = 'https://my-turbobloxels.onrender.com/api';
```

Тогда страница останется на Pages, а данные будут общими.

### 2. Полноценный сервер — общее облако

Нужен Node.js 20+ и место под `data/db.json`.

```bash
npm ci --omit=dev
PORT=3000 TBX_DATA_DIR=./data npm start
```

Варианты хостинга:

* **Render** — в репозитории есть `render.yaml`: New → Blueprint → выберите репозиторий.
  Диск (`disk`) уже описан, чтобы база не терялась при рестарте.
* **Docker / Fly.io / Railway / VPS** — `Dockerfile` собирает образ с `TBX_DATA_DIR=/data`;
  смонтируйте туда том:
  `docker build -t turbobloxels . && docker run -p 3000:3000 -v tbx:/data turbobloxels`.
* Статику сервер раздаёт сам, поэтому отдельный хостинг клиента не нужен.

Проверка: `GET /api/stats` должен вернуть JSON с числами уровней и расширений.

## Происхождение проекта

Проект вдохновлён конструктором **Bloxels** (Pixel Press). Оригинальный веб-клиент Bloxels —
это собранный Unity WebGL-билд (`framework.js.br`, `wasm.br`, `loader.js` + webview-меню):
это не исходный код, а машинный артефакт, который нельзя переиспользовать как библиотеку.
Поэтому TurboBloxels написан с нуля: собственная модель данных, движок, сервер и
расширяемая система блоков. Названия и идеи механик (доска 13×13, цветные блоки, книга
правил) — дань уважения оригиналу; код, тексты и графика здесь свои.
